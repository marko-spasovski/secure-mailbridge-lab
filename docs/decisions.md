- 2026-11-04 · The Wazuh indexer's data lives on a 20 GB encrypted gp3 volume in `persistent`, attached to each session's siem host by `lab` and stopped cleanly before teardown · findings stay searchable across sessions and the dashboard keeps its history, for about $1.90 a month; exporting evidence each session is an extra step that loses search, and losing the data defeats the point of a SIEM
- 2026-11-04 · Wazuh's internal passwords are generated by `persistent` into write-only SSM values under `/siem/`, its certificates are made once on the laptop with `wazuh-certs-tool` and stored by hand under `/siem/`, and siem's role reads `/siem/*` only · no secret on disk outside the host, in the repo or in Terraform state, and the dashboard's certificate stays the same, so the browser trusts its CA once; generating them on each build would change them every session and leave passwords on the host's disk
- 2026-11-05 · Amends decision 89: Wazuh's root CA key is never under `/siem/`; it's encrypted with a passphrase (AES-256) and backed up to `/wazuh-ca/key`, which no instance role can read, with the passphrase off AWS; siem gets `/siem/certs/*` (the CA certificate, and the admin, indexer, server and dashboard certificates and keys), certificates as `String` and keys as `SecureString` like `/vpn/*`; Wazuh's default node names (`node-1`, `wazuh-1`, `dashboard`), SAN `IP:10.0.5.10`, ten-year lifetime · siem reads `/siem/*`, so a CA key there would let whoever controls the SIEM sign certificates the indexer trusts; a host should hold the certificates it presents and never the key that signs them, the same split as the VPN's offline CA (decision 39)
